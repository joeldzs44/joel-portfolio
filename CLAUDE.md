# Working on this repo

## Branching

- Never commit directly to `main`. Every change starts on its own branch and reaches `main` through a pull request.
- Name branches by the kind of change:
  - `feat/<short-name>`: new features or user-facing additions
  - `bug/<short-name>`: bug fixes
  - `chore/<short-name>`: tooling, dependencies, config, docs and cleanup
  - `design/<short-name>`: visual or layout changes with no new behaviour
  - `refactor/<short-name>`: code changes that keep behaviour the same
- Use lowercase kebab-case after the prefix, e.g. `feat/art-gallery-tags`, `bug/contact-form-timeout`.
- Commit and push only with the owner's OK.
